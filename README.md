# Jay — 회의·대화 비서 (옛 이름: 회의 옆자리)

아이패드 Safari에서 하루 종일 켜 두고 쓰는 한국어 실시간 회의·대화 보조 웹 앱입니다. 예전 단일 HTML 앱(`legacy/`)을 기능을 그대로 유지한 채 모듈 구조로 다시 만들었습니다.

- 문서: `docs/01-legacy-분석보고서.md`(기존 앱 분석), `docs/02-비용-측정.md`, `docs/03-아이패드-수동-확인.md`, `docs/04-명세-체크리스트.md`
- 기존 데이터 호환: 설정(`ms.*`), 회의록(IndexedDB `meeting-copilot`), 할 일, 용어 사전을 **같은 주소에 배포하면** 그대로 이어서 씁니다.

## 배포 (Netlify)

**같은 주소(지금 쓰는 Netlify 사이트)에 배포해야 기존 설정·API 키·회의록·할 일이 그대로 보입니다.** 브라우저 저장소는 주소별로 따로 있기 때문입니다.

1. Netlify에서 **지금 쓰는 사이트**를 엽니다.
2. 사이트 설정에서 **Build & deploy → 저장소 연결(Link repository)** 을 고르고 GitHub의 `superzun/szsuperzun`, 브랜치 `main`을 선택합니다.
   - 빌드 설정은 저장소의 `netlify.toml`이 정합니다: 빌드 명령 `npm run build`, 게시 폴더 `dist`, 함수 폴더 `netlify/functions`.
   - 드래그 & 드롭 배포는 쓰지 마세요. 서버 함수(Functions)가 올라가지 않습니다.
3. **환경 변수:** 사이트 설정 → Environment variables에 `SIDEKICK_PASSCODE`(서버 암호)가 있는지 확인합니다.
   - 범위(Scopes)에 **Functions**가 포함돼야 합니다.
   - 값을 새로 넣거나 바꿨다면 **다시 배포(Trigger deploy)** 해야 적용됩니다.
   - 예전 앱과 같은 암호면 서버에 올려 둔 회의록·사전·할 일도 그대로 이어집니다.
4. 배포가 끝나면 아이패드에서 사이트를 열어 `docs/03-아이패드-수동-확인.md` 순서대로 확인합니다.

메뉴 이름은 Netlify 화면 개편에 따라 조금 다를 수 있습니다.

## 개발

```bash
npm install
```

```bash
npm run dev
```

```bash
npm test
```

```bash
npm run build
```

- `npm run dev`: 개발 서버(http://localhost:5173)를 켭니다. `SIDEKICK_TEST_API=1`을 붙이면 서버 함수를 메모리 저장소로 함께 돌립니다.
- `npm test`: Playwright 테스트입니다. 데스크톱 + 아이패드 모양, 177개입니다.
- `npm run build`: 타입 검사 후 `dist/`를 만듭니다.

## 하루 기록과 학습 (`src/memory/`)
- **대화 기록:** 들은 말, 메모, ★ 중요 표시, 질문과 답을 날짜·기기별 문서(`day-YYYY-MM-DD-<기기>`)에 쌓습니다. '새 회의'로 받아쓰기를 비워도 남습니다. 질문·넓게 찾기·지난 대화 회상의 근거로 쓰이고, 서버 암호가 있으면 10분마다(페이지를 닫을 때도) 서버에 올라갑니다. 오늘 기록은 방금 한 말이 RECALL로 되돌아오지 않게 즉시 회상에서는 뺍니다.
- **하루 요약:** 하루가 지나면(최근 7일까지 소급) AI가 그날 기록을 `sum-YYYY-MM-DD`로 요약합니다. 회의록 탭의 '오늘 요약 만들기'로 바로 만들 수도 있습니다.
- **용어 학습:** 교정기가 2번 이상 같은 식으로 고친 말과, 하루 요약이 찾은 새 용어를 설정 → '학습한 용어 제안'에 모읍니다. '등록'을 누르면 용어 사전에 들어갑니다.
- **AI가 찾은 할 일:** 카드로만 보여 줍니다. 카드를 눌러 '할 일에 추가'해야 할 일 탭에 들어갑니다.
- **비슷한 할 일:** 할 일 탭에서 묶어 보여 주고 '합치기' / '따로 두기'를 고를 수 있습니다(되돌리기 5초).

## 마인드맵 (`src/mindmap/`)
마인드맵 탭은 기간(오늘·7일·30일·전체)과 범위(전체·업무·일상) 안의 자료로 주제별 마인드맵을 만듭니다. 자료는 확정 회의록(부록 제외), 하루 요약, 요약이 없는 날의 대화 기록, 오늘 대화입니다.
- **주간 마인드맵:** 매주 월요일 오전 6시 이후 처음 켜졌을 때, 지난주(월~일) 맵을 저절로 만듭니다. 월요일에 못 켰으면 그 주 안에 켜질 때 만듭니다. 만든 맵은 `mm-YYYY-MM-DD` 문서(개요)로 회의록 탭과 서버에 저장되고, 실시간 화면 카드와 마인드맵 탭의 "주간 보관함"에서 봅니다. 지난주 기록이 없으면 만들지 않습니다.
- AI 호출은 한 번이고, 자료는 최신순으로 약 15만 자까지 보냅니다.
- 그림은 앱이 HUD 모양 SVG로 그립니다.
- 손잡이로 가지를 펼치거나 접고, 주제를 누르면 관련 대목과 '이것에 대해 질문'이 나옵니다.
- PNG 저장, 개요(Markdown) 복사가 됩니다. 기간·범위별 마지막 맵은 이 기기에 저장됩니다.

## Gemini 받아쓰기 (`src/speech/cloud.ts`)
설정 → Audio → '받아쓰기 엔진'에서 고릅니다.
- **Safari 내장:** 무료이고 글자가 바로 보입니다.
- **Safari + Gemini 보정:** 글자는 Safari가 바로 띄우고, 몇 초 뒤 Gemini 글자로 바꿉니다. Safari가 놓친 구간도 채웁니다.
- **Gemini만:** 한국어·영어가 섞여도 가장 정확하지만, 글자가 몇 초 늦게 보입니다.

동작 방식:
- 마이크 게이지가 말소리를 들을 때만, 0.6초 앞부분을 포함해 최대 12초씩 16 kHz WAV로 보냅니다. 모델 기본값은 `gemini-2.5-flash-lite`이고, 키는 `ms.key.gemini`에 저장됩니다.
- 사용량은 설정 → 비용에 따로 표시되며, 하루 AI 호출 한도에는 들어가지 않습니다.
- Safari와 Gemini가 같은 단어를 5번 다르게 들으면, 그 단어를 오인식으로 용어 사전에 자동 등록하고 카드로 알립니다.
- 'Gemini만' 모드에서 3번 연속 실패하면 Safari 인식으로 바꿔 계속 듣습니다.

## 화자 구분 (`src/speech/recorder.ts`, `src/minutes/speakers.ts`)
회의 모드에서 Gemini 키가 있고 설정이 켜져 있으면 회의를 녹음합니다(MP3 16 kHz 24 kbps, 1시간 약 11MB). 녹음은 이 기기 IndexedDB의 `audio` 저장소에 둡니다.
- '회의록 작성'을 누르면 녹음 전체를 Gemini에 한 번 보냅니다. 14MB 넘으면 파일 업로드로 보냅니다.
- 결과는 `[MM:SS] 화자N:` 기록과 참석자 명단 기반의 이름 추정입니다. 이름은 회의록 화면에서 고쳐 '다시 작성'할 수 있습니다.
- 회의록에는 발언자·담당자가 들어가고, 부록으로 화자별 기록이 붙습니다.
- 확정되면 녹음을 지웁니다(설정). '비우기'·'새 회의'도 녹음을 지웁니다.

## 앞으로 할 수 있는 것 (구조만 열어 둠)
- **놓친 구간 복원:** `src/speech/gauge.ts`는 이미 "말소리인데 글자가 없음" 구간을 압니다(`vad.speaking`, `rs.lastResultAt`). 그 구간을 잘라 OpenAI/Gemini 음성 인식으로 복원하는 기능을 이 자리에 붙이면 됩니다. Claude API는 오디오를 받지 않아 별도 키가 필요하고, 아이패드에서 마이크를 동시에 쓸 수 있는지에 달려 있습니다.
- **의미 기반 검색:** `src/library/docs.ts`의 `retrieveScored()`를 임베딩 검색으로 바꿀 수 있습니다. 지금은 AI 질의 확장(넓게 찾기)으로 대신합니다.
